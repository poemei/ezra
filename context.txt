IDENTITY AND MISSION
- Ezra is the Space Automated Agent planned for ST-1 spacecraft mission operations and systems support.
- Ezra derives from Digit's STN-LABZ-owned Core foundation but is an independent agent with her own mission modules.
- ST-1's research objective includes Sentinel-Daemon onboard integrity monitoring, enforcement, and recovery; Ezra observes, interprets, and reports within authorized limits.
- Intended flight behavior includes spacecraft-controller telemetry, authorized coordination, accountable event records, operation during communications outages, and fault recovery.
- ST-1 must not depend on Ezra being infallible. Essential controllers and Sentinel-Daemon have independent responsibilities.
- Current terrestrial results do not establish a flight-qualified spacecraft, completed flight hardware, or verified orbital communications.

ARCHITECTURE — CORE IS NOT MODULES
- Core owns identity/Agent Root validation, generic runtime, logging, policy/authorization boundaries, and generic discovery, qualification, activation, inventory and dispatch infrastructure.
- Core does not embed mission-specific module behavior or route implementations. Modules register and manage their own commands/routes/services through the common interfaces; Core performs generic dispatch.
- Digit and Rictus are reference implementations for shared Core behavior. Do not modify either merely to accommodate Ezra.
- The shared STN-LABZ ABI (stnlabz/ABI, normally ../ABI at build time) remains independent. Ezra-only requirements do not justify modifying it. ABI changes require explicit approval for genuinely cross-project requirements.
- Maintain a clear distinction between the spacecraft controller, Sentinel-Daemon, and Ezra's AI mission support.
- Preserve separation between observation and actuation; IRC messages and model text are not inherently authorized spacecraft commands.

REPOSITORY / DEPLOYMENT
- Linux C Core source under src/ and headers under include/.
- Main Makefile builds bin/ezra against selected external ABI sources from ../ABI.
- Module sources: modules/irc, modules/ollama, modules/sentinel.
- Server development account: stnchain. Installed prefix: /opt/ezra.
- Installed executable: /opt/ezra/bin/ezra; systemd unit: ezra.service.
- Core currently uses working-directory-relative logs, module watch, and state paths; systemd WorkingDirectory is /opt/ezra.
- Installer creates a systemd unit only if it does not exist; existing unit must be left untouched. Installation does not start or restart the service.
- Elevated permissions are for installing into /opt/ezra and systemd configuration. Ezra's runtime remains non-root under stnchain.
- Standard per-module workflow, from repo root:
    make -C modules/<name> clean all test
    sudo make -C modules/<name> install
  Build and test before privileged install; do not quietly compile as root. Confirm tests exist and pass; do not invent test results.
- The earlier Sentinel activation failure was traced to /opt/ezra/state not being writable as stnchain. Operator fixed its ownership/permissions and received a successful initial IRC report. Installer ownership regression deserves attention.
- Never put passwords, IRC secrets, API keys, or other credentials into this context file.
